# CI-003 — Isoler la base NVD des refs non fiables

- **Statut :** Prêt pour revue — Pull Request GitHub #10 ouverte
- **Date d'ouverture :** 2026-09-02
- **Responsable de décision :** Porteur du Betting Project
- **Exécutant :** Codex
- **ADR applicables :** ADR-005, ADR-007, ADR-008
- **Branche :** `codex/ci-002-nvd-cache-isolation`
- **Origine :** remarque P1 reçue sur la Pull Request GitHub #9 après sa fusion

## Objectif

Empêcher une pipeline issue d'une ref non fiable de publier une base Dependency-Check ensuite lue
par le contrôle bloquant de `main`, sans réintroduire de clé NVD ni rendre le scan non bloquant.

## Constat et décision

La clé `dependency-check-12-2-2-nvd-json-2-0-${CI_COMMIT_REF_SLUG}` sépare les usages ordinaires,
mais pas les niveaux de confiance : une branche peut modifier son propre `.gitlab-ci.yml` et choisir
explicitement la clé utilisée par `main`. De plus, `main` est volontairement non protégée selon
ADR-008 ; le suffixe serveur entre caches protégés et non protégés ne l'isole donc pas des branches
de développement.

Le job `security:dependencies` ne doit lire aucune archive de cache mutable. Il déclare
explicitement `cache: []` et reconstruit sa base éphémère depuis le flux JSON 2.0 officiel du NVD.
Le chargement à froid d'environ sept minutes mesuré par CI-002 reste compatible avec son timeout de
60 minutes. Un futur cache nécessitera une frontière imposée côté serveur, indépendante du YAML, ou
un feed interne en lecture seule publié par une identité inaccessible aux branches.

## Périmètre autorisé

- désactiver explicitement tout cache GitLab pour `security:dependencies` ;
- interdire par test de contrat toute autre déclaration de cache dans `.gitlab-ci.yml` ;
- corriger l'ADR, le runbook et CI-002 pour refléter la frontière de confiance réelle ;
- conserver le flux NVD JSON 2.0, Dependency-Check 12.2.2, `failOnError=true` et le seuil CVSS 7.

## Exclusions

- aucune clé NVD ou variable sensible ;
- aucune modification des protections GitLab décidées par ADR-008 ;
- aucun cache externe ou service de feed créé sans lot d'exploitation dédié ;
- aucune baisse du ratchet, exception de vulnérabilité ou `allow_failure` ;
- aucune fusion sans nouvelle revue humaine.

## Critères d'acceptation

- [x] `security:dependencies` impose `cache: []`.
- [x] Aucune clé, aucun chemin et aucune politique de cache NVD ne subsistent dans le YAML.
- [x] Le test de garde échoue si un cache est réintroduit ou si le job cesse d'imposer la liste vide.
- [x] Le flux NVD, l'absence d'argument de clé, `failOnError=true` et CVSS 7 restent inchangés.
- [x] Les tests CI, secrets, Maven standard et intégration sont verts avant commit.
- [ ] La Pull Request corrective est revue et sa fusion explicitement autorisée.

## Commandes de test

```text
sh ci/test-dependency-check.sh
sh ci/test-package-guards.sh
./scripts/check-no-secrets.sh --scope all --base origin/main
./mvnw verify
./mvnw -Pintegration verify
git diff --check origin/main...HEAD
```

## Définition de terminé

Le lot est prêt pour revue lorsque les contrats prouvent que le job bloquant ne restaure ni ne
publie de cache GitLab, que la qualification complète reste verte et que la Pull Request expose la
remarque P1 ainsi que sa correction. Sa fusion exige une nouvelle autorisation humaine.

## Résultats d'exécution

- `ci/test-dependency-check.sh` : succès pour les cas clé absente, vide et présente ;
- `ci/test-package-guards.sh` : succès, y compris les contrats GitLab et de reproductibilité ;
- `scripts/check-no-secrets.cmd` : succès sur tout le dépôt et le working tree ;
- `mvnw.cmd verify` : 219 tests réussis, aucun échec, aucune erreur, aucun test ignoré ;
- `mvnw.cmd -Pintegration verify` : 89 tests réussis et cinq migrations validées sur PostgreSQL
  17.10 avec Testcontainers ;
- `git diff --check` : succès.

Le scan à froid n'est pas modifié par ce lot : il utilisera le même lanceur et le même flux que le
passage de 7 min 09 s qualifié par CI-002, mais depuis un espace de travail vide et sans restauration
ni publication de cache GitLab.
