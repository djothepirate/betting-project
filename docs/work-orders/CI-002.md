# CI-002 — Fiabiliser et verrouiller l'analyse des dépendances

- **Statut :** En cours — alimentation NVD et baseline
- **Date d'ouverture :** 2026-09-02
- **Responsable de décision :** Porteur du Betting Project
- **Exécutant :** Codex
- **ADR applicables :** ADR-005, ADR-007, ADR-008
- **Branche :** `codex/ci-002-nvd-dependency-check`

## Objectif

Rendre l'analyse OWASP Dependency-Check reproductible sur GitLab sans inscrire ni afficher de clé
NVD, puis verrouiller le ratchet qui refuse toute vulnérabilité nouvelle de sévérité élevée ou
critique après mesure de la baseline.

## Contexte et décision d'alimentation

Le pipeline GitLab `#2813456672`, exécuté sur `main` au SHA `c8ccf050`, a échoué dans
`security:dependencies`. Dependency-Check `13.0.0` transforme l'absence de clé en chaîne vide et
échoue avant de pouvoir initialiser sa base locale. Cette régression amont est corrigée sur la
branche principale du projet Dependency-Check, mais sa livraison `13.0.1` n'est pas encore publiée.

Le projet GitLab ne contient aucune variable CI/CD. Le lot choisit donc l'alternative sans secret :

- revenir temporairement à Dependency-Check `12.2.2`, dernière version publiée avant la
  régression ;
- conserver la base NVD sous `.m2/dependency-check-data/` dans un cache GitLab propre à la ref et à
  la version de l'outil ;
- ne transmettre l'option `nvdApiKeyEnvironmentVariable=NVD_API_KEY` que lorsqu'une variable
  réellement non vide existe ; la valeur n'entre jamais dans les arguments Maven ;
- réexaminer `13.0.1` dans un lot distinct après sa publication.

Une future clé peut accélérer les mises à jour des refs protégées. Si elle est ajoutée, elle doit
être une variable de projet GitLab masquée, protégée, non développée et limitée à ce seul projet.
La branche `main` restant volontairement non protégée selon ADR-008, le cache par ref demeure la
source d'alimentation opérationnelle de son pipeline.

## Périmètre autorisé

- ajouter un lanceur Dependency-Check qui ne transporte jamais la valeur de la clé NVD ;
- couvrir les cas clé absente, vide et présente par des tests de contrat ;
- isoler et conserver la base NVD dans un cache GitLab par ref ;
- mesurer la baseline élevée/critique sur le SHA du lot ;
- versionner uniquement les exceptions exactes éventuellement nécessaires, avec justification et
  échéance ;
- retirer `allow_failure` et fixer le seuil bloquant à CVSS 7 après mesure de la baseline ;
- documenter l'exploitation, la rotation et la limite liée aux refs protégées.

## Exclusions

- aucune clé, valeur de variable, empreinte de clé ou fixture ressemblant à un secret dans Git ;
- aucune lecture du fichier local de clés API du benchmark ;
- aucune création automatique d'une clé auprès de NVD ;
- aucun cache Maven général partagé entre branches ;
- aucune modification des protections `main` et `release/*` décidées par ADR-008 ;
- aucune suppression globale ou non bornée d'une vulnérabilité ;
- aucune fusion automatique de la Pull Request.

## Critères d'acceptation

- [x] La cause exacte du pipeline `#2813456672` est enregistrée.
- [x] Dependency-Check n'utilise plus la version `13.0.0` défectueuse.
- [x] Une clé NVD absente ou vide ne produit aucun argument de clé.
- [x] Une clé présente est lue par le plugin via le seul nom `NVD_API_KEY`, jamais par sa valeur
  dans la ligne de commande.
- [x] La base NVD est conservée dans un cache GitLab versionné et propre à la ref.
- [x] ADR-008 borne explicitement ce cache à la base publique NVD et maintient l'interdiction du
  cache du dépôt Maven général.
- [ ] Le premier chargement NVD aboutit et produit les rapports HTML, JSON et GitLab.
- [ ] La baseline élevée/critique est mesurée et enregistrée sur un SHA précis.
- [ ] Toute exception de baseline est exacte, motivée, approuvable et assortie d'une échéance.
- [ ] Le seuil CVSS 7 est bloquant et `allow_failure` est retiré après la mesure.
- [ ] Les tests standards, d'intégration, de secrets et de contrat CI sont verts.
- [ ] La Pull Request dédiée reste soumise à revue humaine.

## Commandes de test

```text
sh ci/test-dependency-check.sh
sh ci/test-gitlab-workflow.sh
./scripts/check-no-secrets.sh --scope all --base origin/main
./mvnw verify
./mvnw -Pintegration verify
sh ci/run-dependency-check.sh
git diff --check origin/main...HEAD
```

## Séquence du ratchet

1. Introduire le lanceur, le cache isolé et les tests en conservant le seuil d'observation 11 et
   `allow_failure: true`.
2. Charger la base NVD et produire un rapport complet sur le SHA d'observation.
3. Recenser les seules vulnérabilités CVSS 7 à 10. Les corriger si possible ; sinon créer une
   exception exacte et temporaire, soumise à la décision humaine.
4. Dans un commit distinct, fixer `failBuildOnCVSS=7`, refuser les exceptions devenues inutiles et
   retirer `allow_failure`.
5. Qualifier le diff complet ; la baisse du seuil ou l'élargissement d'une exception exige une
   nouvelle décision humaine motivée.

## Résultats d'exécution

À compléter après la mesure de baseline et les validations finales.

## Définition de terminé

La Pull Request est prête pour revue lorsque la base NVD est alimentée, que le rapport de baseline
est rattaché à son SHA, que les vulnérabilités élevées ou critiques nouvelles font échouer le job et
que les tests prouvent l'absence de clé vide ou en clair dans les arguments. La fusion relève de la
revue humaine prévue par ADR-005.
