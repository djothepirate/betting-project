- **ADR applicables :** ADR-005, ADR-008

## Objectif

Permettre les travaux et snapshots répétés du premier train RC disponible sans changer son nom
`feature/V0.1.0-RC01`. Préserver une finalisation traçable : le POM exact de release appartient au
commit qualifié et n'est jamais réécrit à la volée par le pipeline de promotion.

## État de départ établi

- CI-004 est fusionné par la PR GitHub #13 au SHA de départ ; le run post-fusion
  [34025242715](https://github.com/djothepirate/betting-project/actions/runs/34025242715) qualifie
  ce `main` sous Windows et Linux.
- La feature a été créée à ce même SHA ; son run de seed
  [34025395547](https://github.com/djothepirate/betting-project/actions/runs/34025395547) a réussi.
- Le POM hérité porte `0.1.0-SNAPSHOT`. Les gardes RC de CI-004 n'acceptent ensuite que `rc.N`,
  ce qui impose leur adaptation avant la première PR de travaux `rc.N-SNAPSHOT`.
- Le `main` est synchronisé sur GitLab, mais le pipeline `2824034692` échoue dans
  `validate:source`, sur la contre-épreuve `test-dependency-check.sh` ; sa correction et sa
  qualification sont suivies séparément dans les résultats de ce lot.

## Périmètre autorisé

- aucun élargissement des sources de snapshots durables : seules les branches feature
  d'intégration en pipeline push restent admissibles ; rétention des forges inchangée ;
- aucun changement applicatif Java, migration, profil live, endpoint fournisseur ou déploiement ;
- aucun renommage, réemploi ou effacement des branches et preuves historiques.


L'agrégat s'exécute dans une copie Git isolée contenant le diff et le nouveau WO : il manipule
ses propres références de test et ne modifie aucune référence du worktree de travail. Le test
de packaging utilise son faux Maven/SBOM local et ne constitue pas un build applicatif réel.
Les checks GitHub Windows/Linux du candidat publié restent requis ; ils qualifieront aussi
Maven et PostgreSQL sur le bon SHA.

## Définition de terminé

- **Réalisation locale :** mapping RC cohérent, POM snapshot et documents reliés à la base exacte.
- **Tests :** résultats locaux liés au diff et checks distants liés au futur candidat publié.
- **Revue :** PR vers `feature/V0.1.0-RC01`, checks verts, discussions résolues, revue humaine et
  merge commit ; la clôture effective dépend de cette fusion.
- **Livraison :** snapshot issu du push de la feature après intégration. La finalisation du POM
  relève d'une future PR vers la feature, avant PR finale, synchronisation et MR GitLab.

## Résultats d'exécution

Sur le diff local du 2026-09-06, dans une copie Git isolée de la base exacte ci-dessus, contenant
les fichiers modifiés et le nouveau Work Order :

- syntaxe shell des six scripts modifiés valide et `git diff --check` sans erreur ;
- agrégat complet `sh ci/test-package-guards.sh` réussi, avec
  `BRANCH_NAMING_VERSIONED=PASS`, `GITHUB_PR_POLICY_TESTS=PASS`,
  `GITLAB_WORKFLOW_DEDUPLICATION=PASS`, `GITLAB_MR_POLICY_TESTS=PASS`,
  `RELEASE_REPRODUCIBILITY=PASS` et `PACKAGE_GIT_GUARDS=PASS` ;
- les mêmes versions RC snapshot ont été empaquetées sur GitHub puis GitLab, avec deux IID
  successifs, des contextes de push non créateurs et un `main` différent du sommet feature :
  version, SHA, IID, canal snapshot, absence de tag et `source.train.seed=false` vérifiés ;
- refus d'un autre RC, d'un autre cœur de version, du double suffixe SNAPSHOT et d'un tag RC
  associé à un POM encore snapshot ; garde de PR finale et garde MR conservés stricts ;
- `DEPENDENCY_CHECK_ARGUMENTS=PASS` avec les deux variables de cache héritées. Le défaut initial
  est un faux échec de fixture : GitLab fournit `MAVEN_USER_HOME`, tandis que l'ancienne assertion
  attendait toujours le répertoire `target` de la fixture. Les variables sont désormais
  neutralisées pour ce cas de référence ; deux cas explicites vérifient ensuite le chemin Maven
  et la priorité du répertoire de données configuré, avec des espaces. Le script de production,
  le seuil CVSS et le caractère bloquant du contrôle restent inchangés ;
- scan complet du dépôt et des changements réussi : aucun secret à forte confiance ni endpoint
  privé SofaScore détecté. Le scan du futur commit reste à rattacher au SHA publié.

Le POM est relu comme XML et porte exactement `0.1.0-rc.1-SNAPSHOT`. Ces tests utilisent un Maven
factice pour le packaging ; aucune suite Maven applicative ni Testcontainers n'est revendiquée
comme exécutée localement. Les checks du commit publié et la qualification GitLab de la feature
intégrée restent à obtenir. Aucune finalisation du POM, fusion ou promotion ne découle de ces
résultats locaux.
